# Changelog

Все значимые изменения проекта TRVL документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют [SemVer](https://semver.org/lang/ru/). Даты указаны в формате ISO 8601 (YYYY-MM-DD).

## [1.0.0] - 2026-11-01

Первая версия, где весь путь публикации собран в одном портале. Парсер держит топик и посты forum.awd.ru, блок «Форум» фильтрует их по картинкам, ссылкам, постам и статусу и кладёт тред в форму одним нажатием — целиком или по частям. Форма разбивает длинный текст на последовательные части, даёт каждой свой альбом, заголовок, метки редактора, кнопки-ссылки и панель emoji с русским поиском. Очередь `telegram` уносит это в канал тремя задачами по cron'у — публикацией, периодической правкой и периодическим удалением с архивом. Списки и состояние всякого переключателя живут в сессии и зеркалятся в адрес, блоки обновляются ответом сервера, а числа машины читаются из двух страниц настроек, и сам портал назван TRVL.

### Добавлено

- Ручки переезда альбома в соседнюю часть окрашены синим цветом изображений: бордюр, чернила и заливка при наведении, светлые чернила в заливаемом состоянии
- Тумблер «Кнопки-ссылки в каждой части» переехал из фиолетовой рамки в зелёный блок и показывается при любом числе частей

- Отказ Docker Desktop, из-за которого четыре гейта не удавалось снять, лечится перезапуском приложения: стек поднят, проверки прогнаны заново

### Планируется

- Ревизия чисел, которые до сих пор держит код, а не настройки: границы канала и кнопок-ссылок, возраст зачистки temp, редиректы и пределы пагинации парсера, три числа веб-сервера
- Две страницы настроек сворачиваются в одну «Настройки»: сегодня у каждой свой пункт меню, хотя правят они один и тот же портал
- Поле «Дата и время публикации» будет двигаться вперёд после «Опубликовать» или «Сохранить», а не стартовать тем же слотом, который человек выставил для первой части
- У строки альбома есть переезд картинки в соседнюю часть, но нет стрелок порядка внутри своего альбома: очередь задаётся только порядком заполненных строк

## [0.2.0] - 2026-09-09

### Добавлено

- Страница «Настройки канала» (`site/channel-settings`): форма описания канала до 255 символов и свой пункт меню, активный пункт определяется по текущему маршруту
- Новое описание применяется к каналу запросом `setChatDescription` и только затем фиксируется в базе
- Таблица описаний с архивом: предыдущая активная запись закрывается датой окончания, новая открывается её датой — в одной транзакции
- Блок «Архив описаний» на странице настроек: период публикации и статус «Активен» или «Архив»
- Консольная команда `telegram/set-description` пишет тот же архив, что и страница
- DSN и учётные данные тестовой базы переопределяются через переменные окружения, тесты с базой идут без MySQL
- Тесты архива описаний: закрытие предыдущей записи, равенство дат, первая запись без предыдущей, порядок новые сверху

### Планируется

- Постоянно живущий парсер: пропуск неизменённых элементов, обнаружение обновлений в источнике, дописывание новых
- Текст для описаний канала брать из постов

## [0.1.0] - 2026-09-08

Первая рабочая версия системы парсинга форума forum.awd.ru — исходные данные для канала TRVL: парсинг сущностей со всеми необходимыми данными, организация модели данных и периодический запуск, при котором весь диапазон проходится заново, а записи обновляются на месте.

### Добавлено

- Парсер тем (`forum-parser/scan`, конфиг `awd_forum_topics`): перебор `t` в диапазоне 0–500000, полная структура темы, заглушки для закрытых разделов, а 404 и сетевые ошибки не останавливают проход
- Парсер постов тем (`forum-post-parser/scan`, конфиг `awd_forum_posts`): постраничный обход топиков по пятьдесят постов, все поля поста и автора, дедупликация повторяющегося открывающего поста
- Парсер альбомов галереи (`gallery-parser/scan`, конфиг `awd_gallery_albums`): перебор `album_id`, две таблицы альбомов и изображений, обход пагинации по сто картинок
- Парсер профилей пользователей (`member-parser/scan`, конфиг `awd_forum_members`): две вкладки профиля, нормализация дат phpBB, слияние вкладок в одну запись без затирания полей, которых на страницах нет
- Автоматический вход на форум: HTTP-клиент держит phpBB-сессию и повторяет запрос после страницы авторизации, а без заданных учётных данных работает гостем
- Модель данных PostgreSQL: таблицы конфигов парсеров, участников, тем, постов, альбомов и изображений галереи вместе с сидами диапазонов
- Периодический запуск: cron-контейнер с расписанием каждого парсера, защита от параллельного прохода блокировкой по конфигу и upsert по одной сущности за транзакцию
- Инфраструктура: слоистая архитектура с тонкими console-командами, сервисами сканирования и репозиториями за контрактами, сборка в composition root
- Юнит-тесты парсеров, сервисов, нормализации дат и блокировок; статический анализ без ошибок

### Ручные команды

```
docker compose exec app php yii forum-parser/scan [--from=...] [--to=...] [--limit=N]
docker compose exec app php yii forum-post-parser/scan [--from=...] [--to=...] [--limit=N] [--pageLimit=N]
docker compose exec app php yii gallery-parser/scan [--from=...] [--to=...] [--limit=N] [--pageLimit=N]
docker compose exec app php yii member-parser/scan [--from=...] [--to=...] [--limit=N]
```

### Известные ограничения

- Полный диапазон 0–500000 проходится при каждом запуске, включая несуществующие id
- Оценка времени полного прохода одного диапазона при расписании `*/10`: порядка нескольких дней непрерывной работы
- Ссылки на изображения галереи ведут на файлы форума — при удалении файла ссылка устареет до следующего прохода
- Учётные данные форума лежат в `.env` в открытом виде (для dev-окружения)
